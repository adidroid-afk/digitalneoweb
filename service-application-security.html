Pengertian & Ruang Lingkup

Penilaian keamanan aplikasi end-to-end: pengujian penetrasi web/mobile/API, source code review, pendampingan Secure SDLC, dan manajemen kerentanan berkelanjutan untuk aplikasi enterprise Anda.

Web App Security

OWASP Top 10: injection, XSS, broken access control, session flaws pada aplikasi web dan portal.

Mobile Security

Analisis APK/IPA, penyimpanan lokal, TLS pinning, kontrol bypass root/jailbreak.

API Security

Autentikasi & otorisasi (OAuth/JWT), BOLA/BFLA, rate limiting, validasi input endpoint.

Secure SDLC

Teknik review kode, integrasi SAST/DAST di CI/CD, threat modeling desain.

Perencanaan Layanan

Setiap engagement "Application Security" dipersiapkan melalui tabel perencanaan berikut agar hasilnya terukur, tepat sasaran, dan dapat dipertanggungjawabkan:

Aspek RencanaYang Ditetapkan
Tujuan & kepatuhanKebutuhan regulasi (POJK 11, PCI-DSS, ISO 27001) atau sertifikasi pra-rilis aplikasi.
Ruang lingkup tesDaftar aplikasi/URL/API/versi build, environment (dev/staging/prod), batas eskalasi privilege.
Metode & standarOWASP Testing Guide/WSTG, MASVS, scoring CVSS, pendekatan manual-first + tooling otomatis.
Rules of engagementJendela waktu tes, whitelist IP tester, larangan DoS, data terlarang, contact person insiden.
Izin tertulisSurat izin resmi pemilik sistem + NDA; approval manajemen untuk tes produksi.
Tim & peranLead pentester (OSCP dll.), reviewer kode, PIC klien untuk akun uji bertingkat.
Jadwal & retestTimeline per fase, briefing harian, periode retest perbaikan (mis. 14–30 hari).
Risiko & mitigasiPotensi gangguan layanan — gunakan staging, snapshot DB, dan go/no-go criteria.

Langkah-Langkah Kerja (Delivery Process)

  1. 1

    Perencanaan & Rules of Engagement

    kesepakatan scope, jadwal, kanal komunikasi darurat.

  2. 2

    Reconnaissance & Mapping

    enumerasi endpoint, teknologi, workflow bisnis, dan model ancaman.

  3. 3

    Pengujian Kerentanan Manual

    skenario OWASP/MASVS per fitur: autentikasi, sesi, akses data, upload, logika bisnis.

  4. 4

    Exploitation Terkendali

    membuktikan dampak (impact proof) tanpa merusak data; screenshot & PoC terekam.

  5. 5

    Code Review & Threat Modeling

    audit source code kritis + review arsitektur (SAST/DAST bila tersedia).

  6. 6

    Retest Remediation

    verifikasi perbaikan atas temuan dan penyesuaian skor CVSS.

  7. 7

    Pelaporan & Rekomendasi

    laporan teknis + eksekutif, matriks prioritas perbaikan, workshop findings.

Contoh Kasus

Fintech · Pra-rilis

Temuan blocker pada payment gateway

Pengujian menemukan IDOR yang memungkinkan pengguna A melihat transaksi pengguna B serta kelemahan validasi nominal (price tampering). Setelah remediation + retest, seluruh temuan High tertutup sebelum launch.

Perbankan · Kepatuhan OJK

Gap assessment PCI-DSS & POJK

Regulator meminta bukti pengujian tahunan. Pentest + review konfigurasi menjadi dasar roadmap perbaikan 90 hari dan dokumen evidence audit.

E-commerce

API promo dieksploitasi bot

Coupon stacking via abuse endpoint menyebabkan kerugian margin. Analisis log + pentest mengungkap absennya rate limit dan validasi kepemilikan kupon; diperbaiki dengan token binding.

Aplikasi Mobile

Bypass root detection & fraud

Tes kami memvalidasi jalur bypass penyimpanan token JWT pada perangkat rooted, lalu merekomendasikan hardware attestation (Play Integrity/App Attest).

Deliverable / Hasil Akhir Layanan

Executive Summary

Hasil Code Review

Daftar issue keamanan di source code beserta snippet perbaikan.

Laporan Retest

Status tiap temuan (fixed/partial/accepted risk) pasca-remediasi.

Roadmap Remediasi

Prioritas perbaikan quick-win vs jangka panjang + estimasi effort.

Workshop Knowledge Transfer

Sesi bersama dev team: pola bug, secure coding, pencegahan berulang.
